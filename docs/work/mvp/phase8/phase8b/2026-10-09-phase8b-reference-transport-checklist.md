## Deviations from the plan

1. **Task 2.8 added** (lead ruling P8b-T2): `OutboundHeaderMapper` (task 3.2) carries the zero-length-content rule; task 2.8 landed it in `ToHttpRequestMessage` first and 3.2 moved it.
2. **Argument order.** `SendFailures.Map(native, deadlineFired, caller)` and the `CallDeadline` constructor put the `CancellationToken` last (`CA1068`); the plan wrote it second.
3. **Classification row 1 refined.** With a deadline armed the native client sees a token linked to the caller's, so the exception it throws carries the *linked* token, and the kit's `transport-3` (and `XCUT-1`) require the caller's own. Row 1 therefore returns the native exception as it is only when it already carries the caller's token, and otherwise a new `OperationCanceledException` carrying the caller's token with the native one on its trail (also for an `HttpRequestException` that surfaces while the caller is cancelling). The design table said "as is".
4. **SOCKS credentials (the design's R5, measured).** The runtime asks a proxy's `ICredentials` for a SOCKS proxy with `authType` equal to the proxy scheme (`socks5`, `socks4`, `socks4a`), not `Basic`; the Basic-only credentials answer the scheme per proxy type. SOCKS4 carries a user id only; `socks4a` maps to `Socks4` and resolves locally.
5. **Re-send capability.** The owned construction is re-send capable only for an **HTTP** proxy carrying credentials (a SOCKS handshake has no request to re-send); the design said "`ProxyOptions` carries credentials".
6. **`HttpClient` wraps more than the plan's correction said.** An `IOException` *and* an `InvalidOperationException` from serialisation become an `HttpRequestException`; a `NotSupportedException` and an `SdkException` do not; `HttpContent.CopyTo[Async]` wraps as well. The refused re-send is an `IOException` over the `StreamConsumedException`, as the plan corrected, and the unit rows expect the wrapper. The plan's remark that a missing `WriteTo` is "wrapped by `HttpClient`" is wrong: it is a raw `NotSupportedException`.
7. **The header-refusal branches are mostly defensive.** The native request collection refuses only content-kind headers (a response-kind header such as `ETag` or `Retry-After` is accepted as a custom header), so the plan's "refused by the request collection and not a content header" row has no reachable input. The reachable refusal (a content header with no content to carry it) is tested; the rest is a fallback for a future header kind.
8. **The conformance driver** runs two subjects through one theory (`owned`, `handler`); the handler subject's transport disposes the handler it was given (the caller's job, here the driver's), implements both faces, and builds its hooks over handler chains; its `CreateWithProxy` uses a test-local `WebProxy`. `Only_8b_waivers_remain` became `Only_the_two_recorded_permanent_decisions_remain`. The static constructor that pinned `HttpClient.DefaultProxy` in `SystemNetSubject` is deleted: its cause is gone.
9. **Test placement.** The blocking-pager timeout rows are in `SyncExecuteWireTests` (as the design says) over `PaginationWireTests`' helper types, which became `internal`; the synchronous `traceparent` row is in `TracePropagationWireTests` (it owns the process-wide listeners and its collection).
10. **A test that starved the pool, fixed.** `HeaderDropLogTests` first released 64 callers with a pool-backed `Barrier(64)` under `Parallel.For`; in the project-wide run that stretched the conformance suite past its 20 s bound and failed `transport-9.settle-race-releases` on one subject. It now releases dedicated `LongRunning` threads from a `ManualResetEventSlim` (the knowledge note records the pattern).
11. **The IL scanner skips `Coverlet.Core.Instrumentation`.** Under `--coverlet` the instrumented assembly carries a tracker type whose own code reads the environment; it is not the library's.
12. **AOT smoke.** `CannedHandler` gained `Send` (plan R1), and `CheckPhase8bAsync` (new partial `SmokeChecks.Transport.cs`) runs the handler constructor on both faces, an elapsed deadline on both, a header drop under `Every`, an owned transport behind an unreachable credentialed proxy (which builds the adapter) and a call after dispose.
13. **Pre-existing flake, not touched.** `Dexpace.Sdk.Core.Tests` `OperationSpanLifecycleTests.An_attempt_span_exists_only_under_an_operation_span` failed in 2 of the 6 full-solution runs made while building this phase and passes alone (it listens to the process-wide `Dexpace.Sdk` `ActivitySource`, and a class outside the `Instrumentation` collection can emit on it in parallel); it is the kind of transient 8a's checklist (deviation 13) recorded, and no 8b change touches that suite apart from `LogVocabularyTests`.
14. **The 100 s default deadline also cuts a borrowed `HttpClient` (review finding; breaking change 3, completed; taken here, open for the lead).** The design's options table and breaking change 3 said the default left "no owned-client behaviour"
    changed and "the same observable bound"; that is true of the owned construction only. `CallDeadline.Effective(options, _settings.Timeout)` runs for every construction (P8b-6), so a transport over a borrowed client whose own `Timeout` is longer than 100
    seconds (or infinite) now cuts a call with no `RequestOptions.Timeout` at 100 seconds with a retryable `ServiceRequestTimeoutException`, where on `main` only the client's own `Timeout` bounded it. **Decision: record it, do not change it.** The
    breaking change is stated for the borrowed construction in the `CHANGELOG`, `transport.md` (deadlines section, ownership table, breaking row 3), the package README, the XML remarks of the three borrowed constructors and of
    `SystemNetHttpClientOptions.Timeout`, `docs/first-release.md` (`borrowed-client-default-deadline`) and design §3.3, with the migration `new SystemNetHttpClientOptions { Timeout = null }` (or a longer `RequestOptions.Timeout`), and pinned by four
    `DeadlineTests` rows. The alternative (a borrowed construction defaults to no transport deadline) preserves the old bound, but `(HttpClient)` and `(HttpClient, new SystemNetHttpClientOptions())` would then differ although the options record is the
    same type, and the design, the P8b-6 ruling and the lead's acceptance of the options record all state one default; it is the lead's to take.
15. **A caller `Expect: 100-continue` is a framing drop, not a policy drop (review finding; P8b-T2(a) read).** The ruling orders the `Expect` on the substituted zero-length content "dropped and logged as a drop under the policy". `Expect` is a `TRANSPORT-11`
    framing header that `OutboundHeaderMapper` drops from every request, with or without a body, so the rule needs no code of its own and its log is the framing drop: event 111 (`http.transport.framing_header_dropped`), always `Debug`, whatever
    `HeaderDropLogging` says; event 110, the policy's, is for a header the native client cannot send. Routing the `Expect` through event 110 for a body-less `POST` alone would make one header log differently by whether the request has a body. Pinned by
    `BodylessRetryWireTests` (the wire row asserts the entry's event id; a theory over all three `HeaderDropLogging` modes asserts a single `Debug` entry with id 111 and none with 110; shown to fail with the `Expect` routed through the policy). The lead may overrule.
16. **Phase documents.** Task 2.8 and the `TRANSPORT-2` scope were first recorded only here and in design §3.2/§10; the phase design now carries a dated addendum (scope of 15 rows, exit criterion 2 amended to two permanent waivers, the budget count, the
    borrowed-client deadline) and the plan carries task 2.8 (review finding).

## Open items for the lead

1. **The unmet-MUST budget is exceeded: seven against a target of five (review finding).** The roadmap's parity table allows at most five clauses unsatisfied or unmet on a stated domain. Design §10 records entries 16, 18, 24, 26 and 31 from earlier phases,
   which already used all five, and 8b adds 32 (`TRANSPORT-14`'s name clause, the sixth) and 33 (`TRANSPORT-2`'s native retry for the idempotent methods, the seventh). The rulings P8b-14 and P8b-T2 were taken as "one of the five" and "a second of
   the five"; that premise was false, and 8b cannot cure it: `SocketsHttpHandler` offers no switch for either clause. Phase 11's parity audit must retire clauses elsewhere, re-rule the target, or argue the excess; `docs/first-release.md`
   (*Unsatisfied MUSTs*), design §10's correction and the roadmap note say so, and neither entry describes itself as within the five.
2. **`TRACE` (finding 5 of the roadmap note).** `TRACE` natively writes `Content-Length: 0`, so a zero-length content on it would be wire-identical and would close its retry; the ruling keeps it out (`TRANSPORT-26`, RFC 9110 section 9.3.8). It is a one-line change
   in `OutboundHeaderMapper.CarriesZeroLengthContent`; it shrinks entry 33's residual but does not remove it (`GET`, `HEAD`, `OPTIONS`, `DELETE` remain).
3. **The borrowed-client default deadline (deviation 14).** Recorded as a breaking change, not changed; the alternative is a borrowed construction that defaults to no transport deadline.
4. **The `Expect` log event (deviation 15).** Read as the framing drop; routing it through the `HeaderDropLogging` policy is a change in `OutboundHeaderMapper.Map` and the pinning theory.
