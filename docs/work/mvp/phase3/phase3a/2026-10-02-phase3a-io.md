## Conventions that hold for every task

1. **TDD, in this order.** Write the tests named in the task; run them and see them fail for the stated reason (a compile
   error counts and is the expected red for a new type or changed signature); make the production change; run them green;
   then run the wider gate of the PR's last task. A test that passes before the change is a **pin** and says so; a pin is
   proven able to fail by temporarily breaking the thing it pins (never committed).
2. **Every new `.cs` file** carries the two-line MIT header (`IDE0073`), in `src/` and `tests/` alike, and relies on the
   project's curated `GlobalUsings.cs` only (`ImplicitUsings` is off; every other namespace is imported in the file).
3. **`src/` code**: `ConfigureAwait(false)` on every `await` including `await using` (`CA2007`), methods at most 70 lines
   (`MA0051`), `///` XML docs on every public member (CS1591), no new `PackageReference` in `Dexpace.Sdk.Core`
   (constraint 2: `ArrayPool`, `ArrayBufferWriter`, `MemoryStream`, `Encoding` are in the shared framework). No reflection,
   so `IsAotCompatible` and `IsTrimmable` hold unannotated.
4. **Tests**: `[Trait("Category", "Unit")]` on every class (`TestCategoryTests` enforces it per suite); `Integration` for the
   one wire class; `AotSmoke` for the smoke checks. 3a adds **no** `Security` class and edits none. Core tests live under
   `tests/Dexpace.Sdk.Core.Tests/IO/` (helpers) and `…/Http/{Request,Response}/` (bodies). `Dexpace.Sdk.Core.Tests`
   references Core and `TestSupport` only (SEAM-2), so the wire test lives in `tests/Dexpace.Sdk.Http.SystemNet.Tests/`.
5. **Security tests are never deleted or loosened, and 3a edits none.** `EnsureSuccessErrorMappingTests` in particular
   (the `HTTP-52` re-home) must stay byte-identical and green. Each PR's close-out runs
   `git diff --stat main...HEAD -- tests/Dexpace.Sdk.Http.SystemNet.Tests/Security tests/Dexpace.Sdk.Core.Tests/Security`
   and expects empty output. A change that seems to force an edit there is a signal to re-read design position D and
   `P3a-13`, not to edit the file.
6. **`PublicAPI.Unshipped.txt`.** `PublicAPI.Shipped.txt` is empty, so a changed member is an edit of its line in
   `Unshipped`. Lines are listed per task; the build's `RS0016`/`RS0017` output is the authority (apply the analyzer's code
   fix and compare). Only **PR 5** adds lines; PRs 1–4 and 6 must leave the file unchanged, and the V-gate says so
   (`git diff --stat -- src/*/PublicAPI.Unshipped.txt`).
7. **XML docs mark a breaking change** with `<para><b>Breaking:</b> …</para>` in `<remarks>` of the member it changes,
   stating what it was. The PR's last task adds the matching `CHANGELOG.md` `[Unreleased]` line prefixed **Breaking:**
   where design "Breaking changes" lists it (constraint 8).
8. **Namespace hazard (plan finding F1).** The design puts the helpers in `Dexpace.Sdk.Core.IO`. Inside any
   `Dexpace.Sdk.Core.*` namespace a simple name `IO` now binds to it, so `IO.Path`-style references break. Verified at
   planning time (`grep -rnE "(^|[^.A-Za-z])IO\.[A-Z]" src tests`): no such reference exists today. Code uses `using
   System.IO;` (already a global using) and never `IO.X`. New `TestSupport` doubles use the namespace
   `Dexpace.Sdk.TestSupport.Streams` in folder `TestSupport/IO/` (folder and namespace already differ by precedent, 2b's
   `…Tests.Exceptions`), and Core tests use `Dexpace.Sdk.Core.Tests.IO` as the design says.
9. **One PR per step, code and tests together**; every commit inside a PR is green too. Commit style `feat:` /
   `feat!:` (PR 1 and 5, which carry breaking changes) / `fix:` / `chore:` / `test:` / `docs:`; no AI attribution. **This
   plan authorises no push and no `gh` call**; the lead pushes.

## Plan-level readings (where the design was ambiguous)

The design decisions are not changed. Where it left a point open the plan took the reading most consistent with it:

- **R1 — Internal limit-taking overload.** The design says the cap is "enforced through an internal overload that tests can
  lower". Naming it `ReadAsBytesAsync(long, CancellationToken)` next to the public `ReadAsBytesAsync(CancellationToken = default)`
  invites call-site ambiguity. The plan names the internal members `ReadAsBytesBoundedAsync(long limit, CancellationToken)`
  and `ReadAsBytesBounded(long limit, CancellationToken)`. The public virtual members call them with
  `DefaultMaxMaterializedBytes`. A subclass that overrides `ReadAsBytesAsync` opts out of the cap by overriding; documented
  in the member's remarks.
- **R2 — `BodyTooLargeException` file.** A new file `src/Dexpace.Sdk.Core/Errors/BodyTooLargeException.cs` (the
  design places the type in `Dexpace.Sdk.Core.Errors`, sealed, the three standard constructors, base `StreamingException`).
- **R3 — One decode routine, two-way.** `ReadAsString` and `ReadAsStringAsync` decode through **one** routine (design row
  `IO-13`, Coupling). If 3b's PR 1 has not merged, PR 5 adds it as one `private static string Decode(byte[] bytes,
  MediaType? contentType)` on `ResponseBody` (`Charset ?? UTF8`, `GetString`, behaviour unchanged) and 3b's PR 1 later
  converges it onto `TextDecoding` with the preamble strip. If 3b's PR 1 has merged, PR 5 adds **no** decode of its own:
  the sync reader calls 3b's `TextDecoding.Decode`, so the BOM strip covers both forms. Either way, whichever PR lands
  second converges both readers, and the other's tests pass over the single routine unchanged (task 5.3's convergence
  step).
- **R4 — `IO-9`'s probe byte.** After `DrainUpTo` returns `false` (stopped at the cap), `BodyMaterializer` reads **one byte**
  with a 1-byte buffer (never a zero-count read, `IO-2`); a non-zero result throws `BodyTooLargeException`, zero means the
  body was exactly the cap and the result is returned.
- **R5 — `DrainUpTo` stops at the cap exactly.** It requests `min(chunk, remaining)` bytes with `remaining >= 1`, so with
  `maxBytes == 0` no read is issued and it returns `false` ("end not seen"), preserving "never a zero-count read".
- **R6 — `Utf8LineReader` token.** The sync `ReadLine()` takes no token (design position G); the async form checks the token
  through the underlying `ReadAsync`.
- **R7 — Test-support async bodies.** Test doubles override both `ReadAsync` overloads and both `WriteAsync` overloads
  (fact 1) so a sync-only double cannot mask a pool-thread hop.
- **R8 — Existing `RequestBody` single-use message.** The stream body's second-write message mentions
  `ToReplayableAsync()`; the plan keeps the text and appends "or ToReplayable()" so the sync caller is told too. No existing
  test asserts the exact string (verified by grep of `tests/`).
