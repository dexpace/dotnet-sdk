## Conventions that hold for every task

1. **TDD, in this order.** Write the tests named in the task; run them and see them fail for the stated reason (a compile
   error counts and is the expected red for a new type); make the production change; run them green; then run the stage's
   wider gate. A test that passes before the change is a **pin** and says so; a pin is proven able to fail by temporarily
   breaking the thing it pins (never committed).
2. **Every new `.cs` file** carries the two-line MIT header (`IDE0073`), in `src/` and `tests/` alike, and relies on the
   project's curated `GlobalUsings.cs` only (`ImplicitUsings` is off; every other namespace is imported in the file). Core's
   globals are `System`, `System.Collections.Generic`, `System.IO`, `System.Linq`, `System.Threading`,
   `System.Threading.Tasks`; the core tests add `System.Net.Http`.
3. **`src/` code**: `ConfigureAwait(false)` on every `await` including `await using` and `await foreach` (`CA2007`); methods at
   most 70 lines (`MA0051`); `///` XML docs on every public member (CS1591); no new `PackageReference` (constraint 2); no
   reflection in `src/` (`IsAotCompatible`, `IsTrimmable`); every catch that does not rethrow filters with
   `ExceptionFacts.IsFatal` (§10 entry 12); no `ILogger` call outside `Disposal`. `Dexpace.Sdk.Core.IO` shadows the simple name
   `IO` inside `Dexpace.Sdk.Core.*`: files in the new namespace write `using Dexpace.Sdk.Core.IO;` for `Utf8LineReader` and
   never spell `IO.` (3a finding F1).
4. **Namespace and folder.** Every SSE type, the exception included (P7b-20), lives in `Dexpace.Sdk.Core.ServerSentEvents`, folder
   `src/Dexpace.Sdk.Core/ServerSentEvents/`. The `SSE-37` stray guard fails any core type outside it whose name starts `Sse` or
   contains `ServerSent`/`EventStream`, so nothing SSE-flavoured is ever placed in `Errors/`, `IO/` or `Internal/`.
5. **Tests**: `[Trait("Category", "Unit")]` on every class (`TestCategoryTests` enforces it per suite), `Security` for exactly
   one class (task 2.6), `Integration` for the wire tests. Core tests live in `tests/Dexpace.Sdk.Core.Tests/ServerSentEvents/`
   (namespace `Dexpace.Sdk.Core.Tests.ServerSentEvents`) and use in-memory streams and fakes only (`SEAM-2`). Each test names
   its ID(s) in the method name or a comment. The AOT smoke check is a plain method and carries no trait.
6. **Security tests are never deleted or loosened.** 7b edits **no** existing `Security` class and adds one
   (`ServerSentEventLineCapTests`). The V-gate's diff check is therefore: under `tests/Dexpace.Sdk.Core.Tests/Security` and
   `tests/Dexpace.Sdk.Http.SystemNet.Tests/Security` only the one added file may appear.
7. **`PublicAPI.Unshipped.txt`.** `PublicAPI.Shipped.txt` is empty and stays empty. Only core's `Unshipped` file changes (the
   SystemNet and STJ files must not; the V-gate checks). The file is sorted ordinally and the build's `RS0016`/`RS0017` output
   is the authority: apply the analyzer's code fix after each public type lands and compare against the design's "The public
   surface" list (the design's synthesized-member lines are what the code fix prints).
8. **Test doubles that SSE tests share** live in `tests/Dexpace.Sdk.Core.Tests/ServerSentEvents/` as `internal` helpers, not in
   `TestSupport`, except `SplitReadStream` (task 2.5), which is general and goes to `tests/Dexpace.Sdk.TestSupport/IO/`
   (namespace `Dexpace.Sdk.TestSupport.Streams`; the folder is `IO`, the namespace is `Streams`, plan reading R5).
9. **Commits** follow the repository style: `feat:` for the additive feature commits, `test:` for tests only, `docs:` for
   documentation only. This phase has no breaking change, so no `feat!:`. **No AI attribution** of any kind in a commit message,
   changelog line or document. The plan authorises no `git push`, no `gh` command and no remote action; the closing comment for
   #10 (task 6.5) is drafted text for the lead to post. Branch: `<issue>-phase-7b-sse` off `main`.
10. **Shared files.** `PublicAPI.Unshipped.txt`, `CHANGELOG.md`, `CLAUDE.md`, the roadmap, `tests/Dexpace.Sdk.AotSmoke/
    SmokeChecks.cs` and `SmokeModels.cs` and `Sse37ArchitectureTests.cs` are shared with 7a/7c (design "Shared files"): each
    edit re-derives its hunks from the merged file and never resolves a conflict by keeping either side whole.
    `Directory.Packages.props` and lock files are **not** touched by 7b (P7b-21).
11. **Test timing.** No SSE test sleeps on the wall clock. A test that must wait uses a `TaskCompletionSource` with
    `TestContext.Current.CancellationToken` (`xunit.v3`) and a bounded `WaitAsync(TimeSpan.FromSeconds(10), ...)` as a hang
    guard only.
12. **The parser is pure.** `EventAccumulator` does no I/O; the grammar tests (task 2.2) need no stream. Only the reader, the

## Plan-level readings (where the design was silent, ambiguous or wrong about the tree)

The design's decisions are not changed. **R1–R4 and R8 are corrections of fact; R5–R7 and R9–R10 are additions.**

- **R1 — `SSE-16`'s field set.** The design says the only cross-call state is `_bomChecked`. The reader necessarily holds four
  instance fields: `_lines` (the `Utf8LineReader`), `_accumulator` (reset on every dispatch and on every skipped block),
  `_bomChecked` and `_maxLineBytes` (kept only so the cap exception can name the cap: `Utf8LineReader` keeps its cap private
  and 3a is not edited, P7b-2). Only `_bomChecked` is cross-call event state. There is no `_ended` field: `Utf8LineReader` keeps returning `null` after EOF and the accumulator is empty after
  its one flush, so `SSE-15`'s stable `null` needs no state. The reflection test of task 2.3 pins exactly that set of four
  names and, behaviourally, that a first event's `id` never reaches a second event (`SSE-16`'s "no last-event-id buffer").
- **R2 — Release composes `Disposal` rather than re-implementing it.** `Disposal.DisposeQuietly{,Async}(resource, primary,
  logger)` already does both the "attach to the primary" and the "report out of band" halves (P4b-15: exactly one of the two).
  The quiet and failure-path releases are therefore two calls each (stream, then response). Only the explicit-dispose path needs
  its own try/catch, because it must **propagate** (P7b-12); it collects the stream's failure as primary, attaches the
  response's through `ExceptionTrail.AddSuppressed`, and rethrows with `ExceptionDispatchInfo.Throw`.
- **R3 — `Response.Dispose` disposes its `Body`.** So "exactly one close" (`SSE-23`) is counted on the response's body
  (`TrackingResponseBody.DisposeCount`/a small `SseBody` double), and the opened stream is disposed in addition, first. Both
  latches (`Response`, `ResponseBody`) make a double dispose a no-op, as 3b built them.
- **R4 — The facade's `CancellationTokenSource` is disposed at close.** `CA2213` may be on at `latest-recommended`. Disposing it
  makes `_cts.Token` throw `ObjectDisposedException` for a late iterator; the open step (`OpenAsync`/`Open`, task 3.2) creates its linked source inside a catch-bearing helper carrying the same
  `IsClosedInFlight` and attach clauses as `ReadOneAsync`, so that exception takes the same "closed while in flight" path as every other (P7b-13) and surfaces as `IOException`.
- **R5 — TestSupport's `IO/` folder has namespace `Dexpace.Sdk.TestSupport.Streams`** (`ChunkedReadStream`,
  `DisposeCountingStream`). New TestSupport streams follow that namespace.
- **R6 — `Dexpace.Sdk.Core.Tests` already imports `System.Linq`, which carries `System.Linq.AsyncEnumerable` on .NET 10.** This
  is the environment in which fact 7 matters; task 0.1 runs it in a throwaway app with the same usings.
- **R7 — The stray guard scans compiler-generated nested types.** An async iterator's `<IterateAsync>d__N` is a nested type in
  the same namespace as its owner, so it passes the guard; the plan adds no SSE-named type to the tests assembly that the guard
  could see (it scans `typeof(Request).Assembly`, core only).
- **R8 — `Response` has no logger and `Response.Request.Method` is a `Method` value with `==`.** `FromResponse`'s bodyless test
  is `response.Request.Method == Method.Head`; status is compared by `response.Status.Code` (`204`, `205`, `304`).
- **R9 — `DelegateHttpClient.Create` is the AOT smoke's pipeline transport** (`Func<Request, RequestOptions,
  CancellationToken, Task<Response>>`); `TestSupport` is not available to the smoke project. `DelegateHttpClient.CreateBlocking` returns a bare
  `IHttpClient` (its adapter does not implement `IAsyncHttpClient`), so it cannot sit behind `DexpacePipeline.CreateDefault(IAsyncHttpClient, ...)`; the
  blocking smoke part reuses the async transport and calls `pipeline.Send` (the pipeline terminal bridges through `AsBlocking`), while the facade's `Map`
  still opens the body through `OpenRead`.
- **R10 — `ReadNext` on a closed-over line reader.** The reader builds `new Utf8LineReader(source, LineTerminators.Whatwg,
  maxLineBytes, leaveOpen: true)` and never disposes it (it holds nothing to release); the `CA1001` waiver is
  `[SuppressMessage("Design", "CA1001", Justification = "SSE-17: the reader never owns its source, so it has nothing to dispose.")]`.

    public bool Equals(ServerSentEvent? other) { /* five fields; Data via Enumerable.SequenceEqual(..., StringComparer.Ordinal); string fields ordinal */ }

public sealed class ServerSentEventReader
{
    public const int DefaultMaxLineBytes = 1_048_576;
    private readonly Utf8LineReader _lines;
    private readonly EventAccumulator _accumulator = new();
    private readonly int _maxLineBytes;   // only so TooLong can name the cap; Utf8LineReader keeps its own private (P7b-2)
    private bool _bomChecked;

    public ServerSentEventReader(Stream source, int maxLineBytes = DefaultMaxLineBytes)
    {
        _lines = new Utf8LineReader(source, LineTerminators.Whatwg, maxLineBytes, leaveOpen: true);
        _maxLineBytes = maxLineBytes;   // after the line reader has validated it
    }

    public ServerSentEvent? ReadNext()
    {
        while (true)
        {
            string? line;
            try { line = _lines.ReadLine(); }
            catch (InvalidDataException ex) { throw TooLong(ex); }
            if (line is null) { return _accumulator.Flush(); }
            if (_accumulator.Accept(StripBom(line)) is { } dispatched) { return dispatched; }
        }
    }

    public async ValueTask<ServerSentEvent?> ReadNextAsync(CancellationToken cancellationToken = default) { /* same, ReadLineAsync(...).ConfigureAwait(false) */ }

    private string StripBom(string line)   // sets _bomChecked on the first line ever read (SSE-12, P7b-3)
    private ServerSentEventLineTooLongException TooLong(InvalidDataException inner) => new(_maxLineBytes, inner);
}
