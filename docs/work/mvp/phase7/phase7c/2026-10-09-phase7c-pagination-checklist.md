  every assertion on every request the transport saw. A cross-origin, network-path (`//evil.example`), scheme-downgrade or other-port `next` target ends the walk after one exchange and no request
  reaches the other origin; a same-origin target is followed with the policy's own stamp; a userinfo-bearing same-origin target is followed with the userinfo removed; a first page that redirected
  to another origin does not license following links there (the origin compared is the template's). The `allowCrossOrigin: true` behaviour is a `Unit` fact
  (`PaginationStrategiesTests.With_allowCrossOrigin_the_walk_follows_and_per_call_auth_stamps_the_credential_for_the_new_origin`) so it can change without touching this class.

## Deviations from the plan

1. **Task 0.1 (pre-flight) results.** Facts 1 to 6 hold on 10.0.401 exactly as the design states (`GetComponents` rebuild, `Uri.Query`, `TryCreate` accepting `not a url` and a TAB, `?page=2`, `//evil.example/x`,
   `EscapeDataString`, `int.TryParse` of an Arabic-Indic digit and a leading space under `NumberStyles.None`); the phase-start queries match the design (36 canonical IDs, 0 gaps, no PAGE note or conflict); the baseline
   was 24 + 25 = 49 tests. No ruling was reopened. The Ruby test sources are absent locally and were not fetched (design R3, plan R9): every row had a conformance case from the Node ports, so the lead's authorisation
   for a GitHub read was not needed.
2. **Tooling.** In the Microsoft.Testing.Platform mode of `dotnet test`, the MSBuild flags the task required (`-m:3`, `-nr:false`, `--disable-build-servers`) are forwarded to the test application as unknown arguments
   (`Zero tests ran`, exit code 5). Builds ran with the flags (`dotnet build … -m:3 -nr:false --disable-build-servers`) and tests with `dotnet test --no-build --max-parallel-test-modules 1`;
   `scripts/ci/reproducible-pack.sh` ran through a `DOTNET` wrapper that appends the flags to restore, build and pack.
3. **`IPageStrategy.Parse`'s third parameter is named `first`, not `template`.** CA1716 rejects the reserved word on an interface member. The documentation calls the value the template throughout; the parameter doc says so.
4. **The blocking read does not call `ResponseBody.ReadAsBytes`** (the plan's task 2.4 and R1 said it would). `ReadAsBytes` also closes the body (BODY-16), so a release failure would surface from the read, before the
   strategy ran, and could never be a suppressed secondary of a parse failure (`PAGE-13`). `PageStep` opens the stream and reads it through `BodyMaterializer.ReadAll` under the same 64 MiB cap, leaving the body to the
   response's own close; `BlockingPageableTests.A_page_envelope_over_the_materialisation_cap_fails_with_BodyTooLargeException` pins the cap.
5. **The plan's wire row 2 (a `RequestOptions.Timeout` that fires `ServiceRequestTimeoutException`) is not built.** `SystemNetHttpClient` accepts `RequestOptions` and reads none of it until phase 8b wires `Timeout`
   (TRANSPORT-5; `SystemNetHttpClientTests.Options_are_accepted_and_ignored_until_8b`), so there is no timeout to fire. The row is replaced by `PaginationWireTests.A_cursor_walk_hands_the_same_RequestOptions_instance_to_the_real_transport_on_every_page`,
   which is `PAGE-36`'s real claim at the seam. The plan said to record a dropped row as a deviation from the spec's test table; this is that record.
6. **The `PAGE-33` late-response pin is in `PageStepTests`, not only in the lifecycle suite.** With the discard removed the lifecycle row still passes (the cancelled read also closes the response and throws
   `OperationCanceledException`); the step test asserts the serde is never called, which is the discard.
7. **The fatal-exception pin was built.** The plan allowed recording a gap because `OutOfMemoryException` is awkward to raise; throwing a hand-made instance from a strategy is safe, so
   `PageStepTests.A_fatal_exception_is_not_intercepted_by_the_close_path` asserts the exception propagates and nothing is disposed.
8. **Test doubles.** `EnvelopeBody` (a valid-envelope body that counts and can fail its release, with an `onDispose` callback so a test can order closes against yields) joined `PageFixtures` and `EnvelopeSerde` in the Core test
   project; nothing in `TestSupport` changed. The lifecycle suite wraps the blocking pager in an `IAsyncEnumerable` so one set of rows drives both pagers.
9. **`PublicAPI.Unshipped.txt`** was edited from the analyzer's RS0016/RS0017 text (applied by a script, inserted beside the existing pagination lines). The record `FetchedPage<T>` kept its positional shape with an
   explicit backing field for the validated `Page`; the compiler accepted it, so the plan's non-positional fallback was not needed. `Pageable<T>` lives in `PageableOfT.cs` (the file header says why).
10. **Gate scheduling.** Group 1's gate ran restore, build, format, the full test run and both `Security` filters; the heavier ones (AOT publish, pack, dependency audit, reproducible pack, tools, `verify-structure`, probe) ran at the end of
    group 2 and again at the end of group 3, under the task's resource limits.
11. **§11 item 66** is the next free number on this branch's copy of the design. 7a and 7b may take the same number in parallel; renumber at merge.
12. **Knowledge corpus.** Nothing found contradicts a harvested entry, so no note was added under `docs/knowledge/notes/`.
13. **Review corrections (2026-10-09).** Three verified findings were fixed after the group commits. (a) The 7c documents described the blocking pager's gap as only "sync-over-async inside the transport", which
   implied it works over `SystemNetHttpClient`; it throws `NotSupportedException` there because `HttpResponseMessageBody` has no `OpenRead` until 8b. The text above, `Pageable<T>`'s and `CreateBlocking`'s remarks,
   `pagination.md`, the design's 8b row, hand-off and R5, design §7.1's dated correction and the roadmap note now say so; the wire test above pins it; **`HttpResponseMessageBody.OpenRead` is named as the blocking
   pager's 8b prerequisite** (the roadmap already lists it among 8b's work). (b) `QuerySplice` stripped every leading `?` from the raw query, rewriting an untargeted parameter whose name starts with `?`; it now strips the
   one delimiter. (c) `QuerySplice`'s rebuild dropped the zone id of a scoped IPv6 host, which `System.Uri` keeps only in `IdnHost`; it is restored from there. (b) and (c) each have `QuerySpliceTests` rows (`PAGE-21`, `PAGE-24`) that failed before the fix (7 of the 48 `QuerySplice*` tests) and pass after it.
