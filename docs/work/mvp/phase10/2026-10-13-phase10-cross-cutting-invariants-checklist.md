# Phase 10 — Cross-Cutting Invariants and Non-Functional Requirements: Checklist

The execution-time checklist for roadmap phase 10 ([phase card](../2026-09-27-dotnet-sdk-v1-roadmap-design.md)): one row per requirement ID, in the legend of the roadmap's cross-cutting constraint 3. Written from what was built on branch
`99-phase-10-cross-cutting-invariants` (issue #99), following the [design](2026-10-13-phase10-cross-cutting-invariants-design.md) and the [plan](2026-10-13-phase10-cross-cutting-invariants.md). User page:
[`cross-cutting-invariants.md`](../../../sdk-documentation/cross-cutting-invariants.md), with the suites in [`conformance.md`](../../../sdk-documentation/conformance.md).

The scope is the **41 rows phase 10 owns** (`XCUT-1` to `XCUT-24`, `NFR-1` to `NFR-17`; 26 MUST and 15 SHOULD by appendix C: `XCUT` 22 MUST + 2 SHOULD, `NFR` 4 MUST + 13 SHOULD): **39 ✅ / 0 🚫 / 2 ⏳ / 0 N/A**. Ten of the 39 ✅ are split (`XCUT-1`, `-4`, `-13`, `-23`, `-24`, `NFR-1`, `-4`, `-12` on an existing §10 entry, a vacuous clause or
a declined one; `XCUT-8` and `XCUT-20` on readings) and none adds an unmet MUST. The two ⏳ are `NFR-16` (no release path yet, phase 12) and `NFR-17` (the workflow half is built and pinned; the repository-ruleset half is an admin action the lead has not made, see *Open items*). The plan's four stacked pull requests were built as
**four commit groups on the one branch**, in the plan's order (contract and invariant suite; codec suite; packaging suite and gates; appendix B, coverage and close-out), each ending green at its gate task; nothing was pushed. The kit gains three suites (47 assertions: 28 invariant, 11 codec, 8 packaging) beside the 43 transport assertions, each
with a negative control, and the transport drivers stay green with exactly their two permanent waivers per SystemNet-family driver.

**Red evidence.** Taken where it was informative, and said as it was: most suites were written test-first against a deliberately broken subject (`Controls/`), so for every assertion the red is the control failing for its stated "Because" reason, which each control row pins (`InvariantControlRow` checks the failure text, not only that it failed). What was measured on top, mutations performed and reverted (never committed):
`BoundedMap`'s capacity multiplied by 100 turned the core driver red on `xcut-14.bounded-under-burst` and `xcut-14.drains-after-insert`; the single-registration check in `ServiceSlot.Install` made a no-op turned the DI driver (`xcut-23`) and `SingleRegistrationTests` red; `AddTristateSupport` commented out at both sites in `SystemTextJsonSerde` turned the STJ driver red on `serde-15` to `serde-20`;
a scratch file with a `ConcurrentDictionary` constructor and `Exception.GetBaseException` gave exactly two `RS0030` errors, and the two bans added without the `BoundedMap.cs` pragma gave one `RS0030` at `BoundedMap.cs(49,16)`; the six new `# Re-enable when:` lines stashed turned `AnalyzerWaiverTests` red naming six blocks; `Seam2ArchitectureTests` was red against the kit before its allow-list edit; a deliberately wrong pinned list
in the AOT smoke (`xcut-9` removed) made the published binary exit 1; the packaging step over a package whose nuspec dependency version was edited exits 1 naming `nfr-2` and `nfr-14`. The reproducible pack: with `-p:DeterministicSourcePaths=false` on both packs, the **old** same-directory script passes (it cannot see a path leak), the **new** cross-path script fails with all five packages differing,
and without the flag the new script passes with five byte-identical packages (design V3). Not taken: a mutation run (Stryker.NET refuses the Microsoft.Testing.Platform projects, P10-21).

## Deviations from the plan and the design

1. **Four commit groups on one branch**, not four branches: the plan's per-PR branch names were ignored by instruction; each group ends at its own gate task (1.13, 2.x, 3.12, 4.10) and each was run green before the next began.
2. **27 skipped tests, not 22.** The plan (0.1) expected no new skipped rows. The five additional skips are the pinned `NotExercised` rows of the first-party invariant drivers (P10-28, R13): the core driver's `xcut-23.resolution-deterministic` (only the DI driver supplies `SeamResolution`) and the DI driver's four (`xcut-8.strict-factory-rejects`, `xcut-9.cycle-safe-walk`,
