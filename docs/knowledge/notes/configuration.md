## Superseded
- **An empty environment value is absent, not a `ValidateOnStart` failure.** Supersedes `configuration/bfbcbf8c` ("an environment variable set to the empty string is a present, empty value to `IConfiguration`, and binding it into a typed option fails `ValidateOnStart`"): the binder maps an empty value to `null` for a nullable target (V1), and the DI package's reader treats an empty or whitespace-only value as absent, so the record default applies and a lower provider's value that the empty one shadows is not consulted (`CFG-2`, design §10 entry 25, P9-7). The shadowing is silent: it is a recorded asymmetry (`di-empty-shadows`, `docs/first-release.md`) and an open ruling for the lead. *Superseded by the phase 11 note below: the shadowing is gone when the registered configuration is the section's root.*
  <sub>review · `docs/work/mvp/phase9/2026-10-12-phase9-host-integration-checklist.md` · high · sha:manual-p9-empty-is-absent</sub>
- **An empty or whitespace-only value is absent and falls through to the next provider that has one, when the registered `IConfiguration` is the root that holds the section.** Supersedes the phase 9 note above on the shadowing: V11 of phase 11 walked `IConfigurationRoot.Providers` from the top, skipped a blank `TryGet` and read the lower provider's value under an empty environment variable; a `ChainedConfigurationProvider` exposes its own `Configuration`, so the walk recurses into it; and `root.GetSection(section.Path)` enumerating exactly the pairs the caller's section does is how the reader knows the section belongs to that root. A section from a configuration the container does not hold, or one that is not a root, keeps the merged read, where the empty value wins and the record default applies (`CFG-2`, design §10 entry 25, §11 item 68, P11-17; `EmptyValueTests`). That residual is a counted unmet clause (the fourth, found by the 2026-10-21 review: no public API reaches the root of an `IConfigurationSection`, so the package cannot walk the providers of a configuration it was not given); `di-empty-shadows` is narrowed in `docs/first-release.md`, not removed.
  <sub>review · `docs/work/mvp/phase11/2026-10-19-phase11-deviation-reconciliation-design.md` · high · sha:manual-p11-empty-falls-through</sub>
- **`OBS-35`'s layered level lookup is satisfied by the DI package's reader, not by `IConfiguration` binding.** Supersedes `observability/4997350a`: both binder modes admit a numeric level (`"2"` becomes `Body`) and an undefined one (`"7"` is accepted silently), so binding alone cannot meet `OBS-35`'s recognised-names rule; the reader parses `Logging:Level` by name only and fails a number or an unknown name naming the key and listing the names (design §10 entry 26 now touches `OBS-35`).

## Conflicts
- **The configuration binder is not the reader; the DI package reads `IConfiguration` itself.** Departs from the styleguide companion's `csharp-aspnetcore/01-host-and-configuration.md` 1.3 ("the Options pattern is the only sanctioned reader") and from design §8.2's binder-plus-registered-converters text (P9-4, open for the lead): neither binder mode can serve (V1), so an internal reader walks the section by known keys with the package's own grammars and builds the records with `with`. No consumer code indexes `IConfiguration`, which is 1.3's intent; the reader is the binding layer itself, and the options pattern still carries the result (`ValidateOnStart`, `IStartupValidator`). `ConfigurationBinder` is banned in `src/`.
  <sub>review · `docs/styleguide/csharp-aspnetcore/01-host-and-configuration.md` · high · sha:manual-p9-binder-departure</sub>
- **`AddDexpaceClient` returns a `DexpaceClientBuilder`, not the service collection.** Departs from `csharp-aspnetcore/02-dependency-injection.md` 2.7 ("a feature extension returns the collection so calls chain"): the `IHttpClientBuilder` precedent; `builder.Services` chains back.

## Conclusions
- **The configuration binder's source generator binds no `init` accessor and says nothing, and its reflection mode is not AOT-safe and mis-binds.** Over the repository's option records (V1): the generator leaves every value of every record at its default (`MaxRetryAttempts = "5"` stays 2, `BaseDelay = "PT5S"` stays 200 ms, `Level = "Body"` stays `None`), fails to compile over `ProxyOptions` (`CS9035` for the `required` members) and reports `SYSLIB1100`/`SYSLIB1101` for `IReadOnlySet<Method>` and `ICredentials`; the reflection mode raises 32 `IL2026` and 32 `IL3050` warnings, sets `init` accessors (surfacing an accessor's exception as `TargetInvocationException`), reads a `TimeSpan` `"1000"` as 1000 days and rejects `"PT5S"` and `"500ms"`, accepts an `int` `"0x10"` as 16, accepts a `bool` `" TRUE "`, maps an enum `"7"` to the undefined value 7, silently does not bind `IReadOnlySet<int>` or `IReadOnlySet<Method>`, and **appends** to an `IReadOnlyCollection<string>` default instead of replacing it.
  <sub>review · `docs/work/mvp/phase9/2026-10-12-phase9-host-integration-design.md` · high · sha:manual-p9-v1-binder</sub>
- **`XmlConvert.ToTimeSpan` is not `CFG-7`'s duration grammar.** It reads `P5M` as 150 days and `P1Y` as 365, `-PT5S` as minus five seconds, rejects lower case (`pt5s`) and truncates `PT0.00000001S` to zero (V2); `int.TryParse` with `AllowLeadingSign` accepts `010`, `-5`, `+3` and rejects `" 5 "`, `0x10`, `1_000`, `1e3`, `1.5`, non-ASCII digits and overflow. The DI package's reader has its own duration grammar (the ISO day-time subset with a seven-digit fraction, `<n><unit>`, bare milliseconds) over an ASCII trim.
  <sub>review · `docs/work/mvp/phase9/2026-10-12-phase9-host-integration-design.md` · high · sha:manual-p9-v2-grammars</sub>
- **`ValidateOnBuild` does not run options validation, and `ProxyOptions.FromEnvironment` reads `NO_PROXY` only once it found a proxy.** A provider built with `ValidateScopes` and `ValidateOnBuild` does not run `IValidateOptions`; `ValidateOnStart()` registers `IStartupValidator`, whose `Validate()` runs the named validators with no host, and a keyed factory that reads `IOptionsMonitor<T>.Get(name)` fails lazily at first resolution (V4). Two keyed registrations under one key resolve silently to the last.
