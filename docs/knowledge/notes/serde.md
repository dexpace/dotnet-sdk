## Superseded
- **The lazy typed-response wrapper is a compare-and-swap on a `TaskCompletionSource<T>`, not `Lazy<Task<T>>`.** Supersedes `pipeline/972ff44d` and `pipeline/f4b0fc98`: design §7.3's `Lazy<Task<T>>` in `ExecutionAndPublication` mode holds its monitor across the factory's *synchronous* prefix, which for a buffered body is the whole parse, so concurrent first callers block a thread, the .NET form of what `HTTP-45` forbids. Measured on 10.0.401 in phase 7a's pre-flight: eight threads over a factory that sleeps 500 ms each waited about 500 ms (`[500,500,500,500,500,500,500,500]`); on the compare-and-swap only the winner did (`[500,0,0,0,0,0,0,0]`). `TypedResponse<T>` therefore memoizes success and failure in a task completed by `TrySetResult`/`TrySetException`, runs the parse under the construction token, and lets a caller's token cancel only its own wait. Phase 7a ruling P7a-15.

## Conclusions
- **A source-generated context in `GenerationMode.Serialization` (the fast-path-only mode) carries no property metadata, so it serves only its own options object and cannot carry the Tristate modifier.** Verified on 10.0.401: with the context as the resolver of any *other* `JsonSerializerOptions` (the serde's private copy), serialising a type with a custom-converter property throws `InvalidOperationException` ("did not provide property metadata for type"), with or without a `WithAddedModifier`. A default-mode context honours `ShouldSerialize` (Absent is omitted) and so does a `Metadata` one. `SystemTextJsonSerde` copies the caller's options (`SERDE-26`), so it cannot use a fast-path-only context; the documentation says to use the default or `Metadata` mode, and `TristateJsonTests.A_fast_path_only_context_cannot_carry_Tristate_models` pins it.
  <sub>review · `docs/work/mvp/phase7/phase7a/2026-10-09-phase7a-serde-checklist.md` · high · sha:manual-p7a-fast-path</sub>
- **A value-type `JsonConverter<T>`'s `Read` receives the JSON `null` token at the root, as an array element and as a property value, and never receives a missing key.** Verified on 10.0.401 with `HandleNull` overridden to `true`; a missing key leaves the member at `default`, which is `Tristate`'s Absent. Writing, an Absent array element and an Absent dictionary value degrade to `null` (`SERDE-20`) because `ShouldSerialize` applies to properties only.

- **A `switch` expression over an enum that names every member is still `CS8524`, so a test of an exhaustive state `switch` needs a discard arm.** `TreatWarningsAsErrors` fails the build otherwise; `Tristate`'s `State` switch is therefore asserted as "covers every named state", not as compiler-enforced exhaustiveness.

- **A fault rethrown from a discarded task surfaces as `TaskScheduler.UnobservedTaskException` on the finalizer thread, in whichever test happens to be running.** `TypedResponse<T>` rethrows a fatal exception (`OutOfMemoryException`) from its parse task after recording it (`P7a-15`); a test that provokes it must subscribe, force a collection from a separate frame and mark only its own exception observed, or `LateResultTests` (which counts the event process-wide) fails at random.
