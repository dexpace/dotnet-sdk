## Superseded
- **The SSE line reader is phase 3a's `Utf8LineReader` in `Whatwg` mode, not a second byte reader over an `ArrayPool<byte>` buffer, and the BOM is stripped at the string level.** Supersedes `sse-streaming/095e7bd1`: 3a built the reader with a 4 KiB `byte[]` per reader (a per-stream array on a long-lived stream is not a pooling win), a mandatory line cap, a CR that ends the line at once and `leaveOpen`, so 7b reuses it unchanged (plus one internal `IsFailed` accessor). The parser's one persistent flag removes a leading U+FEFF from the first line it reads, which is byte-equivalent to a three-byte `EF BB BF` check: a decoded string starts with U+FEFF only for those bytes (verified on 10.0.401: `EF BB` and `EF BB 41` decode to U+FFFD).

- **The raw view is `ServerSentEventReader.ReadAllAsync(Stream)` and `ReadAll(Stream)`, named after `ChannelReader.ReadAllAsync`.** Supersedes `sse-streaming/f74b5238`: `ReadAsync(Stream)` would sit beside the instance `ReadNextAsync` and read as a single read. Each view is lazy, builds one reader at its first pull (so the BOM is per stream), validates its arguments at the call and throws `InvalidOperationException` at the second `GetEnumerator` / `GetAsyncEnumerator`.

## Conclusions
- **A type implementing both `IEnumerable<T>` and `IAsyncEnumerable<T>` makes LINQ ambiguous on `net10.0`, so `ServerSentEventStream` is `IAsyncEnumerable` only and the blocking view is `AsEnumerable()`.** Verified on 10.0.401 with `System.Linq` imported: `.Where(…)` and `.Select(…)` on such a type fail with `CS0121` between `System.Linq.Enumerable` and `System.Linq.AsyncEnumerable`; an `IAsyncEnumerable`-only type binds the async operators. `ToBlockingEnumerable` on the facade would be sync-over-async, which `AsEnumerable()` (a real walk over `Stream.Read`) avoids.

- **The reference transport's response body needed a synchronous `OpenRead` before the blocking SSE views worked over a real socket.** `HttpResponseMessageBody` inherited the base `NotSupportedException` (P3a-5 left it to phase 8b), so `AsEnumerable()` and `Map` threw over `SystemNetHttpClient`; phase 7b added the override, sharing the open latch with `OpenReadAsync` and reading `HttpContent.ReadAsStream`, and `ServerSentEventWireTests.A_blocking_Map_over_HttpPipeline_Send_round_trips` pins it on a loopback socket.
